# Telegram警报

独立重写的 Pine Script v6 指标，无外部库依赖。用于标准 **5分钟** USDT 加密货币现货/永续图表，发现放量与振幅同时异常；不下单。

## 默认条件

全部同时满足才触发：
- 当前振幅大于前20根已完成K线平均振幅的3倍。
- 当前成交量大于前20根已完成K线平均成交量的3倍。
- 当前交易对24h成交额 **严格大于1亿USDT**；等于1亿不触发。
- 可选最低振幅过滤默认关闭，预设0.5%。

默认即时触发，每根K线最多一次。可切换收盘确认；冷却分钟默认0（关闭）。冷却从实际实时触发起计算，重新加载或重建警报会重置。历史背景只表示收盘数据满足条件，不模拟盘中触发或冷却；即时信号重载后可能与历史背景不同。

振幅=(最高-最低)/最低×100；当前涨跌幅=(收盘-开盘)/开盘×100。均值不包含当前K线。不按已过秒数外推成交量，不添加趋势/涨跌幅方向限制。

## 24小时数据及限制

使用一分钟数据计算最近1440根一分钟K线成交额，并验证1440分钟跨度连续及成交量有效；不足24小时、缺失数据、未知单位、错误周期或非标准K线时显示暂停原因，不报警。
- 报价币单位：直接累计成交量。
- 基础币单位：使用每分钟HLC3×成交量估算成交额，不等于逐笔成交额。
- tick或未知单位不猜测；第一版仅支持报价币USDT。币本位、USD/USDC等不在本版支持范围。
- 24h涨跌幅使用一分钟序列中1440分钟前的收盘价作基准。
- 数据精度为一分钟，当前分钟未结束时为部分数据；并非精确到秒的交易所24小时统计。
- 只统计当前交易所/当前交易对，不是全网成交额。低周期请求历史覆盖受TradingView套餐与数据源限制。

## 文件

- `指标源码.pine`：复制到Pine编辑器，添加到5分钟图表。
- `Telegram警报消息.json`：用于TradingView警报消息。chat_id是占位符，必须替换。
- `指标说明.md`：本说明。

## Telegram Webhook设置

1. 将新指标添加到标准5分钟USDT图表，确认右上角“已就绪”。
2. 在指标设置中选“即时”或“收盘确认”，再创建新警报，条件选择 **Telegram警报 → 波动警报**。
3. 即时模式在警报窗口选择“每根K线一次”；收盘确认选择“每根K线收盘时”。不要把即时模式与窗口的收盘频率混用，否则盘中信号可能被忽略。
4. 把JSON文件全部内容粘贴到消息框，将聊天ID占位符替换为自己的ID，保留双引号。不要把真实ID提交到公共仓库。
5. Webhook URL填写 `https://api.telegram.org/bot<你的BotToken>/sendMessage`，只在TradingView内替换Token。机器人需能向对应聊天/群组发消息；频道需相应发帖权限。TradingView Webhook要求开启双重验证。
6. 保存警报后检查TradingView警报日志与Telegram接收结果。源码或参数更新后重建警报；既有警报保存的是旧快照。

JSON采用纯文本，不设置parse_mode，避免Markdown特殊字符错误。命名plot占位符已作JSON引号转义；不要删除反斜杠。价格使用{{close}}，保留品种报价精度；百分比、倍数和亿成交额在脚本内四舍五入至两位，小数显示格式最终由TradingView占位符替换决定。消息时间为UTC。模板标题不宣称已收盘，适用于两种模式。

此指标不会自动扫描红色自选列表；普通图表警报只针对创建时选定品种。多品种需分别创建，或另行验证账户支持的自选表警报功能。本次不更改已有警报、不自动发送Telegram消息。

## 验证

2026-11-09：TradingView Pine v6编译通过，OKX BTCUSDT永续5分钟图运行显示“已就绪”；设置面板核对20/3/3、成交额1亿、最低振幅关闭、即时、冷却0。15分钟图显示暂停提示，测试后恢复5分钟。JSON可解析且7个命名占位符与源码匹配。未进行真实Webhook发送、Telegram送达或跨K线冷却实盘验证。

输入默认隐藏状态行；曲线仅在窗格显示，默认隐藏价格轴标签和状态行值。平台复选框状态不能由源码强制改写。
